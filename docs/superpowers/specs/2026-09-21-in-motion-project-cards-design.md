# KEIMA「CURRENTLY IN MOTION」專案卡片設計規格

日期：2026-09-21  
狀態：使用者已確認視覺方向 A

## 目標

重新設計 `CURRENTLY IN MOTION`，使它與 `HOW WE MOVE` 的橫向文字列形成清楚差異，並恢復先前較理想的「大型圖片＋專案資訊」呈現。

本次只處理專案展示區，不變更其他區段的內容與版型。

## 內容範圍

只呈現目前已確認的三個真實專案，不新增推測或虛構內容：

1. JOBSGAME — Game Industry Career Platform
2. INDIE GUIDER — Independent Game Media
3. GAMECF — Digital Game Crowdfunding

沿用現有中英文說明與正式網址。三個專案等權呈現，不建立主次層級。

## 視覺方向

桌面版採三欄大型專案卡。每張卡由兩個主要區塊組成：

- 上方大型媒體區：暫時使用 KEIMA 品牌化幾何佔位圖。
- 下方資訊區：專案名稱、英文分類或標籤、外連箭頭；現有簡介保留並以次要層級呈現。

整體延續網站既有的克制顧問品牌語言：米白背景、黑色主體、KEIMA 青色作為動態與導引重點。卡片不使用圓角、浮誇陰影或通用漸層。

## 品牌化幾何佔位圖

三張圖片共用同一套視覺規則，但構圖不可完全重複：

- 使用黑、米白、KEIMA 青三色。
- 以斜切、跨越、位移、框線與棋步感作為構圖語彙。
- 每張圖帶有小型專案序號／分類標記。
- JOBSGAME、INDIE GUIDER、GAMECF 各自使用不同幾何組合，維持系列感同時具備辨識度。
- 幾何佔位圖以 CSS 裝飾元素完成，不依賴新圖片資產。

未來取得正式專案圖片後，只替換媒體層，不改動卡片資訊結構與響應式網格。

## 版面結構

### 區段標題

保留現有：

- 區段序號 `03`
- 小標 `In Motion`
- 標題 `CURRENTLY IN MOTION`
- 簡介文字

標題區下方接三欄卡片，不再使用與 HOW WE MOVE 相同的表格式橫列。

### 桌面版

- 三張卡片等寬並列。
- 卡片圖片採約 4:3 比例，形成足夠的視覺重量。
- 三張卡片頂端、圖片底線與資訊區基線一致。

### 平板版

- 採兩欄網格。
- 第三張卡片保留單欄寬度並對齊左欄，右欄留白；不跨滿兩欄，以免製造錯誤的主次暗示。
- 卡片寬度與間距以既有內容容器為準。

### 手機版

- 單欄堆疊。
- 圖片調整為較寬幅比例，避免三張大型圖片讓長卷軸過度拉長。
- 文字與箭頭維持清楚點擊區，不縮成密集資料列。

## 互動與動態

- 有正式網址的專案，整張卡片都是外部連結。
- Hover／鍵盤 focus 時，幾何構圖只做小幅位移，青色線條產生短距離掃動，箭頭向右上方移動。
- 不使用大幅縮放、3D 翻轉或持續循環動畫。
- 延續現有 Reveal 進場，三張卡依序錯開少量時間。
- `prefers-reduced-motion` 啟用時，取消位移與進場動畫，內容保持完整可見。

## 元件與資料邊界

- 沿用 `ProjectList` 與既有 `inMotion.projects` 資料，不建立第二份專案內容。
- `ProjectRow` 改名為語意明確的 `ProjectCard`；元件只負責顯示單一專案與安全網址。
- 幾何圖形可由專案 `id` 對應 modifier class，避免把視覺資料寫入內容檔。
- URL 安全檢查維持現況，只允許 HTTPS 外部網址。

## 無障礙

- 專案清單繼續使用有序清單語意。
- 連結可透過鍵盤聚焦，focus 樣式不得只依賴色彩。
- 幾何佔位圖為裝飾用途，從輔助技術隱藏。
- 連結的可存取名稱包含專案名稱與分類。
- 顏色與文字對比須維持 WCAG AA 可讀性。

## 驗證標準

- 單元測試確認三個真實專案均渲染，且不再使用 `.project-row` 表格式版型。
- 測試確認每張卡均有大型媒體區與安全 HTTPS 連結。
- 響應式瀏覽器測試確認桌面三欄、平板兩欄、手機單欄。
- 所有既有路由、雙語、導覽、減少動態與水平溢位測試保持通過。
- 正式建置、型別檢查與 lint 必須通過。
